# Combined dependency file for CI and single-manifest deploy platforms.
# Streamlit Community Cloud auto-discovers only requirements.txt /
# pyproject.toml at the repo root -- a custom name (this file used to be
# requirements-deploy.txt) is silently ignored, which was a real deploy
# bug fixed by this file existing under this exact name. Local dev
# instead installs requirements-core.txt (pandas-free engine) and
# requirements-app.txt (API/UI) separately -- see README "Local setup" --
# keeping that split is what proves the engine has no web dependency;
# this file just unions both for the one-manifest cases.
-r requirements-core.txt
-r requirements-app.txt

# Editable install of this repo's own `cde` package (pyproject.toml
# declares it). Locally, `cde` was importable because dev setup did a
# one-time `pip install -e .` into the venv by hand -- Streamlit Community
# Cloud only ever runs this file, so without this line `cde` is never
# installed there at all. Streamlit's `streamlit run app/streamlit_app.py`
# puts app/ (the script's own directory), not the repo root, on sys.path
# -- so `from cde.config import ...` fails with ModuleNotFoundError on
# Cloud even though the file layout is identical to local. `-e .` (not a
# plain `.`) so local dev edits to cde/ are picked up live without a
# reinstall, same as the by-hand install it replaces.
-e .
