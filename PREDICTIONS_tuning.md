# CineGraph Explore tuning -- pre-registered predictions

Written and committed **before** any crosstab code exists. Checkable in this
branch's git log: this file's commit precedes the commit adding
`cde/tuning.py` / crosstab output. Phase 1 (crosstabs) is report-only and
gated -- compute, report, stop for confirmation before touching any scoring
code in `cde/explore.py`.

Source: the labeled 120-row eval (`eval/explore_eval_labeled.md`, a human
pass over `eval/explore_eval.md`, generated by `eval_explore.py` per
`PREDICTIONS.md`). Counts confirmed by re-parsing the file programmatically
before writing this: 60 `interesting` / 48 `trivial` / 12 `wrong`; of the 60
non-interesting, 47 `weighting-limited` / 13 `data-limited`.

**Disclosure, same reason as last time:** to compute `crosstab_B`'s temporal-
implausibility flag, `cde.people.load_people()` needs `birth_year`/
`death_year` on `person` -- name.basics columns the original `imdb-people`
load didn't carry (only `nconst`, `primary_name`). Extending that schema
(additive, nullable columns, no existing query changes) and re-running it
against the real `film.duckdb` is being done as *data preparation* for this
phase, before any crosstab is computed, and is disclosed here rather than
folded in silently. It touches `cde/people.py`, not `cde/explore.py` --
scoring stays untouched through all of Phase 1.

## Predictions

**(P1) Cross-director collaborator edges dominate the `interesting` class;
same-director results dominate `trivial`.**

Precisely: for each labeled row, "same-director" means a person credited as
`director` on *both* the seed and the result (the same check `novelty`
already uses internally, not a string-match on the explanation column).
Predicted: `interesting` rows are disproportionately cross-director (the
lateral jump to a different director via a shared cinematographer/composer/
editor/writer); `trivial` rows are disproportionately same-director (more of
one filmography). This is `crosstab_A`: judgment x same-director/
cross-director.

Falsified if: same-director and cross-director rows split roughly evenly
across `interesting`/`trivial`, or same-director rows are judged
`interesting` about as often as cross-director ones -- would mean the
auteur-collapse story isn't what's actually driving the `trivial` label, and
a same-director penalty would be fixing the wrong thing.

**(P2) The `wrong` / data-limited edges are temporal outliers.**

Precisely: either (a) a large release-year gap between seed and result, or
(b) the connecting person's plausible active window can't span the older of
the two films -- `birth_year > min(seed_year, result_year)` (credited on a
film before they could plausibly have been born) or `death_year <
min(seed_year, result_year)` (credited on a film released after they died).
(b) is the rescore/re-release signature (a 2013 composer "connecting" a 1925
film to a 2020s rescore). This is `crosstab_B`: judgment x year-gap bucket
(0-15 / 16-40 / 41+ years), plus a separate count of how many of the 12
`wrong` rows the temporal-implausibility flag (b) catches on its own.

Falsified if: `wrong` rows are spread evenly across year-gap buckets, or the
temporal-implausibility flag catches only a small minority of the 12 --
would mean the `wrong` cases are a more varied/entity-level problem (like the
already-known Eros/The Hand mislabeling) than a clean temporal rule can
address, and the gate would need to be scoped down or reconsidered.

## What Phase 1 does NOT do

Compute and report `crosstab_A`, `crosstab_B`, and the temporal-flag catch
count on the 12 `wrong` rows, then stop. No change to `cde/explore.py`
scoring, no config flags added, no re-run of `eval_explore.py`. That's Phase
2, gated on confirmation that P1/P2 held against the actual crosstabs -- if
they don't, the two fixes in the brief aren't justified as written and get
rethought rather than applied blind.
